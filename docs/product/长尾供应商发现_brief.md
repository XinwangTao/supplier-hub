# 长尾优质供应商发现 — 需求 Brief

日期：2026-10-29　状态：待确认

## 要解决的问题

现有 101 家供应商全部来自 A 股上市公司名单，**都是"谁都知道"的大厂，管理它们没有边际价值**。
真正有价值的是发现**价格便宜、质量也不差的中型供应商**——它们不出名、不在公开榜单上，但能在供应链里稳定交付。

## 范围

**In scope**
- 跨行业发现候选供应商（不限定细分行业）
- 规模口径：参保人数 100–500 人（中型）
- 用企查查数据做"体检"：规模、资质、行政处罚、经营异常、专利、中标记录
- 输出可人工复核的候选池 + 评分排序

**Out of scope（本阶段明确不做）**
- 价格数据：公开源不可靠，留到询价环节由人工获取
- 验厂、样品测试、商务谈判
- 大供应商管理（现有 101 家保留，不再扩展）

## 数据源现实（2026-10-29 实测）

| 源 | 能否发现供应商 | 实测结论 |
|---|---|---|
| 企查查 MCP | ❌ | 只能"企业名→详情"，无行业/规模检索，不能用于发现 |
| A 股年报 | ⚠️ 很弱 | 年报仅披露前五大供应商**合计金额与占比**，通常不写名称；只有招股书/问询回复才常披露名称，覆盖面窄 |
| 政府采购网 | ⚠️ 可抓 | 搜索页可达但返回"频繁访问"反爬页，需低频、限速 |
| 中国招标投标公共服务平台 | ⚠️ 待验证 | 首页可达，检索接口未验证 |
| 1688 / 阿里巴巴 | ✅ 最可能 | 中小供应商最集中，且有价格区间；反爬严格 |
| 人工名录（展会、协会、同行推荐） | ✅ 确定可用 | 需要用户提供入口 |

**结论**：没有单一源能自动产出"便宜+优质"名单。可靠做法是**多源半自动发现 + 企查查人工可控的体检**。

## 主流程

1. **圈定搜索词**：按品类/工艺关键词（如"注塑件""连接器""SMT 代工"）
2. **多源发现**：招投标中标记录 / 1688 供应商 / 人工名录 → 原始候选名单
3. **标准化去重**：企业名归并，剔除已入库的 101 家与上市公司主体
4. **企查查体检**：参保人数 100–500、资质证书、行政处罚、经营异常、专利、招投标记录
5. **质量评分**：资质权重 + 风险扣分 + 规模贴合度 + 中标活跃度
6. **输出候选池**：按分排序，标注证据链接
7. **人工复核 → 询价 / 验厂**（价格在此环节获得）

## 成功标准

- 单批次能从公开源产出 ≥50 个**非上市公司**候选主体
- 其中 ≥30% 参保人数落在 100–500 区间
- 每个候选都有可点击的数据溯源（企查查信用代码 + 源链接）
- 人工复核时，至少一半候选"值得打一个电话"

## 约束

- 企查查积分有限（单 Key 约 100 次），体检环节必须支持队列与断点续跑
- 反爬源需限速，不能高频抓取
- 价格不在本阶段，避免设计依赖不存在的数据

## 关键风险

1. 公开源覆盖不足，候选池可能大量来自人工名录 → 需要用户提供行业入口
2. 企查查参保人数与实际产能不完全对应（劳务派遣、多基地）
3. "质量高"只能靠代理指标，最终必须靠询价/打样验证
