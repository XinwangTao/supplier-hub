# 供应商五维档案(人·机·料·法·环)Brief

## 用户与问题
采购/审核团队巡厂时掌握的供应商现场数据,现有系统无法承载:当前供应商档案只有工商信息(企查查)与工艺能力标签(经营范围推断),视角停留在"能供什么"。需要按 **人·机·料·法·环(4M1E)** 五维存储供应商综合能力的**事实信息**。

**这是信息存储,不是评分**(QCDST 管评分,互不替代)。

## 数据来源(用户明确)
**全部人工录入**——巡厂现场掌握的数据,不自动抓取、不从经营范围推断。

## 五维字段草案
- **人**:员工总数、参保人数、研发人员数、**部门分布**(品质部/开发部/业务部/生产部/高层管理,可自定义部门,各多少人)、关键人员(高管/质量负责人)
- **机**:厂房面积、产线数、关键设备清单(名称/型号/数量/役龄)、自动化率、产能利用率
- **料**:主要原材料及来源地、关键物料双源情况、来料检验方式(IQC)、材料合规(RoHS/REACH)
- **法**:体系认证(ISO9001/IATF16949/ISO13485 等)、专利、设计/检测能力、工艺文件完备度、变更管理
- **环**:环境体系(ISO14001)、环保处罚记录、能耗与三废处理、所在地

## In / Out of Scope
**In**:五维数据模型与存储(Postgres)、SRM 工作台录入表单(按五维分区)、录入留痕(录入人/时间/全量快照,可回查)、供应商档案页五维分区展示
**Out**:自动评分(不动 QCDST)、企查查自动抓取、权限体系、多租户隔离(五维是供应商全局客观事实)、CSV 批量导入(后续需要再说)

## 成功标准
1. 审核员能在 SRM 给任意供应商录入五维信息,保存后留痕可查
2. 供应商档案页按五维分区展示,缺失字段显示"—"(不推断、不填充,遵循项目数据哲学)
3. 数值校验:人数/设备数非负、比例 0–100%,非法输入拒绝保存

## 主路径场景
巡厂员在 SRM 选择供应商 → 按五维分区填写现场数据 → 提交校验 → 通过则全量快照留痕保存 → 档案页按五维展示。
失败/兜底:校验失败标错回到表单;数据修正 = 重新录入,旧快照留痕可回查。

## 关键约束
- 全部字段人工录入,企查查字段不自动混入五维
- 缺失显示"—",绝不填看似合理的值
- 录入留痕追加式,支持回查(呼应项目 L4 审计壁垒)

## 借鉴调研(≤15 行)
- 4M1E(人机料法环)为 SQE 行业通用供应商稽核框架,字段结构对齐标准稽核表;外部可比开源项目弱,声明不外搜
- 对架构的直接影响:
  1. `domain.Supplier` 扩展五维 JSON 结构列(Postgres)
  2. 新增 SRM 五维 API(读/写/历史)
  3. DetailPanel 新增五维分区;SRM 工作台新增录入入口
