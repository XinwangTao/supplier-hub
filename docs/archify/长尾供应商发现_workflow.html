长尾优质供应商发现 — 工作流

目标：发现参保 100–500 人、有资质、无风险的中型供应商，而不是再扩大厂名单。v1.0 / 2026-10-29 / 待确认
输入 处理 人工节点 产出 失败/人工出口
N1

品类 / 工艺关键词

例如「注塑件」「连接器」「SMT 代工」；跨行业时按品类分批，每批一个关键词。

E1 关键词
N2

多源发现

已验证：中国政府采购网（Playwright 抓中标公告，可拿到供应商名+金额）。受限：1688 强制登录，无 cookie 不可自动抓。兜底：人工名录（展会、协会、同行推荐）。

E2 原始候选
N3

标准化去重 · 排除大厂

企业名归并、统一社会信用代码对齐；剔除已入库 101 家与上市公司主体。

E3 净候选名单
N4

企查查体检

参保人数 100–500 筛规模；抓资质证书、行政处罚、经营异常、专利、中标记录。走队列，断点续跑。

E4 体检结果
N5

质量评分

资质权重 + 风险扣分 + 规模贴合度 + 中标活跃度；输出分值与证据链接。

E5 排序候选
N6

候选池

按分排序，每个候选附信用代码、关键指标、源链接；写入 supplier_candidates.json。

E6 人工复核
N7

人工复核

看产线、看案例、打电话。淘汰明显不合适的，标注「值得跟进」。

E7 跟进名单
N8

询价 / 打样 / 验厂

价格只在这里产生——公开数据拿不到真实报价，必须人工询价。验证通过后进入正式供应商库。

失败 / 人工出口

X1

源反爬或无结果

政府采购网返回「频繁访问」、1688 触发验证 → 降速重试，仍失败则转人工名录（退回 N2）。

X2

企查查配额不足

返回 402 / credit_balance_insufficient → 候选进队列挂起，换 Key 或充值后续跑（N4 断点）。

X3

名称多候选 / 查不到

返回「多候选」不自动选择 → 人工确认主体，或用信用代码直查。

X4

评分不合格

有行政处罚 / 经营异常 / 规模偏离 → 进淘汰池，保留记录避免重复查询。

本图的前提判断：企查查只能"查证"不能"发现"——它没有行业/规模检索接口。发现必须靠外部源，且没有单一源能自动产出可靠名单， 因此流程设计为「多源半自动发现 + 企查查可控体检」。
已验证的不利事实：A 股年报通常只披露前五大供应商合计金额与占比、不披露名称；政府采购网搜索页有反爬。这两点决定了 N2 必须保留人工名录入口。
刻意不做的：价格预测、自动验厂、大供应商扩容管理。
