# 平台定位与数据壁垒

> 本文是**工程约束**，不是商业计划书。设计决策必须能回溯到这里的某一条。
> 完整的推演过程在 Obsidian 笔记《供应商寻源台》（定位 / 五层护城河 / 数据矩阵 / 用户旅程）。

## 一、定位

**供应商的「美团」**：供应商是商家，采购企业是用户，平台用真实履约数据替代不可验证的主观推荐。

三个必须照搬的机制：商家自维护店铺、真实交易评价、就近优先。
五个不能照搬的地方（B2B 与 B2C 的硬差异）：

| 差异 | 后果 |
|---|---|
| 客单 30 万、决策 30 天 | 分数必须可下钻到证据链，不能只给一个总分 |
| 供给非标（CNC 也分三六九等） | 卡片必须挂工艺能力/设备/精度，不能只有"主营" |
| 切换成本 3-6 个月 | 卖点是"筛选与准入效率"，不是"更便宜" |
| 用户是企业（多角色） | 权限要能按角色裁剪 |
| 数据合规更严 | 来源必须可查、授权可证；**假数据是法律风险，不只是体验问题** |

**冷启动顺序不可反**：SRM 单边工具 → 单体 QCDST → 寻源侧开放 → 网络效应。
先做黄页再补交易，就成了企查查；先做工具再开黄页，才是美团。

## 二、五层壁垒与代码对应

| 层 | 壁垒 | 代码对应 | 状态 |
|---|---|---|---|
| L1 | 数据覆盖（**门票，不是壁垒**） | `ingest/`、`provider/qcc`、`catalog/` | 已有 |
| L2 | 履约数据（**核心，买不到**） | `srm/` 订单-交付-IQC-8D → `qcdst/` | 已有 |
| L3 | 网络效应（跨买家聚合） | `service/supplier_ops.go` 按样本量加权 + `RatedBuyers` + `Spread` | 已有 |
| L4 | 转换成本（工具→系统） | SRM 沉淀 + 审计留痕 `srm/audit.go` | 部分 |
| L5 | 合规授权 | 数据来源字段、demo 标识、待补的授权链 | 部分 |

**L2 的硬约束**：QCDST 的任何分数都必须能追溯到具体单据 ID，**不提供人工调分入口**。
一旦有"手动改分"，销售就会拿它换订单，壁垒当场瓦解。

**L3 的硬约束**：单个买家的数据不产生壁垒，跨买家聚合才产生。因此：
- 单买方权重上限（防止一家企业把评级拉满或拉死）
- 必须披露分歧度 `spread`（均分掩盖分歧，分歧才是真相）
- 样本不足（<15 批）一律"观察期 / NA"，不与已评级供应商混排

## 三、数据分层（访问控制规范）

| 层 | 谁 | 可见范围 |
|---|---|---|
| L0 公开 | 任何人 | 名称、城市、主营、能力标签、评级**等级**、已验证企业数 |
| L1 认证 | 已认证采购方 | 评级分数、五维明细、证据链、股东/人员、资质编号 |
| L2 合作 | 已建立 SRM 关系 | 联系方式、精确地址、订单评分卡、8D 报告、报价 |
| L3 自有 | 数据产生方 | 自己录入的全部数据，**可导出** |

两条设计原则：

1. **公开层给等级不给分数**。等级够支撑"要不要进一步了解"；分数会被批量采集拼榜、脱离上下文传播。
2. **联系方式锁在 L2**。这既是防爬，也是促转化——要电话就得走引入流程。

不可导出的清单：股东与人员明细、精确办公地址、客户名单、联系方式、报价历史、其他人贡献的履约数据。
可导出的清单：企业自己录入的订单/交付/事件（那是它的资产，不给导出不合理）。

## 四、接口层执行规则（当前强制项）

| 规则 | 实现 |
|---|---|
| 无任何导出端点（CSV/Excel/批量下载） | 不实现，不预留 |
| 单页条数服务端硬上限 | `service/service.go` `Search` |
| 频率限制 | `policy` 中间件，按 IP 令牌桶 |
| 响应水印 | 响应头 `X-Trace-Id`，可反查泄露源 |
| 策略机器可读 | `GET /api/v1/meta/policy` |

**为什么"不给导出按钮"不够**：按钮是 UI，接口才是事实。只要接口返回字段，F12 或 curl 三分钟就能拖走。
所以防护必须在服务端：字段裁剪、条数上限、行为限流、水印溯源。**前端隐藏字段属于假防护。**

**限流的定位要说清**：单 IP 600 次/分，只能拖慢爬取，拦不住会换 IP 的对手。阈值也不能定太紧——
企业出口常是几十人共用一条 NAT，定成 240 次/分时，第一个被误伤的是正常客户，不是爬虫。
它的作用是**提高低成本爬取的时间成本**，真正的墙是字段分层与关系门槛。

## 五、变现红线

可卖：供应商认证与展示位、采购侧 SRM 订阅与寻源配额、脱敏聚合洞察报告。
**不可卖**：评级分数与等级、默认搜索排序、其他企业的原始履约数据。

卖评级 = 评级不再是决策依据 = 平台退回广告位。这条没有例外。

## 六、下一步（按性价比）

1. **字段分层裁剪**（服务端 DTO）：列表只给卡片字段，明细按 tier 返回 —— 当前所有字段无条件返回，是最大的口子。
2. **企业认证 + 账号体系**：分层的前提。
3. **供应商自助门户**：双边闭环的另一半，也是 L1 数据新鲜度的来源。
4. **询价代联**：不暴露电话也能撮合，解法比"先认证再给电话"更顺。
